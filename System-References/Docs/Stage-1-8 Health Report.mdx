## Executable Readiness Model

Run a stage finalization audit with:

```sh
python3 .opencode/Skills/global-stage-readiness-audit/scripts/run_readiness_audit.py \
  --stage 6 \
  --proposed-status ready_for_stage_7
```

The runner:

1. verifies the stage's required files
1. parses all applicable JSON
1. validates files against repository schemas
1. resolves stable IDs and file-plus-JSON-Pointer references
1. checks canonical completion and handoff data
1. enforces Stage 1-4 decision approval
1. checks assumption and risk recording
1. checks high and critical risk authority
1. checks artifact-registry presence where required
1. checks launch-critical workflow, dead-control, and fixture-runtime gaps
1. checks applicable visual and design continuity
1. writes revision loops for every blocking gap
1. writes `Stage-X-readiness-audit.json`
1. updates `Global-workflow-state.json`

Ready results exit zero. Non-ready results preserve the failed audit and exit nonzero.

## Scoped Change Layer

Preview a change route with:

```sh
python3 .opencode/Skills/change-intake-router/scripts/route_change.py \
  "Redesign the project list page without changing behavior"
```

The minimal implementation supports:

- active-stage refinement detection
- deterministic earliest-stage routing
- proportional validation levels
- explicit approval before durable record creation
- clean-worktree preflight before recording
- compact `CHANGE-NNN` records
- a ledger containing only record references, status, base commit, and affected-ID locks
- single-writer stable-ID conflict detection
- completion auditing for schema, approval, locks, unresolved impact, deferred work, and high-risk evidence
- `ready_to_merge` only after a passed audit
- Stage 6 one-ticket scoped input without false full Stage 5 completion

Deliberately excluded:

- automatic branches, worktrees, commits, pushes, or merges
- semantic JSON merging
- automatic rebasing
- parallel writes to the same stable ID
- a second baseline or snapshot store
- Stage 9

These exclusions keep the implementation inside the approved lean scope.

1. **Contract and enforcement now share one path**

   The global audit is no longer only prose. It produces durable machine-readable pass and failure results.

1. **Outcome evidence beats artifact presence**

   Launch-critical workflows must work through UI, route/action, persistence/service, visible result, and evidence.

1. **Stage 5 remains a strong executable model**

   Its normalized package, canonical collections, manifest, resolver, scope checks, wave checks, and workflow obligations remain the deepest stage contract.

1. **Frontend continuity is unusually complete**

   Stage 4 through Stage 7 preserve interaction IDs, page structure, design rules, visual references, evidence, responsive behavior, accessibility, and launch risk.

1. **Risk acceptance is no longer ambiguous**

   Agents may propose or escalate high and critical risks but cannot silently accept them.

1. **Change handling avoids full-pipeline waste**

   Approved changes route to the earliest affected owner, lock only affected IDs, and preserve unrelated canonical outputs.

1. **Packaging is mechanically enforceable**

   Future skill additions now fail a repository test if required metadata is missing.

## Remaining Limitations

### 1. Real-App Stage 1-8 Evidence Is Still Pending

Impact: **medium**

The isolated golden path proves the executable contracts compose, but it does not replace a real application run with actual research, architecture, previews, implementation, deployment, monitoring, and feedback.

Next action:

```text
Run one supervised application through all eight stages and retain the generated readiness evidence.
```

### 2. The Schema Validator Intentionally Implements The Used Subset

Impact: **low to medium**

The stdlib validator supports the schema features currently present: references, pointers, types, required properties, enums, constants, `allOf`, `anyOf`, `oneOf`, conditional `if/then/else`, item counts, string patterns, and numeric bounds.

It is not a general replacement for every Draft 2020-12 keyword.

Upgrade condition:

```text
Adopt a standards-complete validator only when a repository schema introduces an unsupported keyword.
```

### 3. Summary Matching Is Structural

Impact: **low**

The readiness runner verifies Stage 5-8 summary presence, stage identity, and canonical JSON validity. The summary generator remains the source for detailed canonical-content rendering; the audit does not perform semantic natural-language equivalence.

### 4. The Change Router Does Not Mutate Git Automatically

Impact: **low**

This is deliberate. The router performs clean-worktree and base-commit checks but leaves branch, worktree, commit, push, merge, and post-merge operations to the approved Git workflow.

### 5. Stitch Remains An External Capability

Impact: **low**

Stage 4 now performs and records a capability preflight and handles partial or unavailable tools through explicit fallback approval. Repository code cannot guarantee external service availability or authentication.

### 6. Draft Templates Need Real Usage Evidence

Impact: **low**

Graduation criteria now exist, but draft templates should remain draft until they accumulate three completed Stage 4 uses across two products with responsive, accessibility, routing, and gap-resolution evidence.
