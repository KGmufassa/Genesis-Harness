# Layout Pattern — card-grid

Use when:

- users browse visually distinct items
- images, previews, summaries, or non-uniform item content matter
- comparison is lightweight

Avoid when:

- users need dense field comparison
- sorting, filtering, and bulk edit workflows dominate
- many rows require consistent operational scanning

Requires:

- card anatomy
- responsive column counts
- empty and loading states
- accessible card click behavior and nested-action rules
